# 腾讯 A 股只读日线：配置与验收

腾讯现在是独立、可明确选择的国内日线源。沿用已合并第一阶段的工具链；默认仍为东方财富，不自动切换数据源。公告/定期报告索引仍由东方财富提供，数值报表及舆情等缺口没有因新增行情源而变为可用。

## 配置

```python
from tradingagents.dataflows.config import run_config
from tradingagents.dataflows.router import route_to_vendor

with run_config({"ashare_data_enabled": True, "ashare_price_vendor": "tencent"}):
    result = route_to_vendor("get_stock_data", "000001", "2026-10-20", "2026-10-28")
```

CLI 或正式研究运行可设置以下非敏感变量；此处没有新增数据 Key：

```bash
export TRADINGAGENTS_ASHARE_DATA_ENABLED=true
export TRADINGAGENTS_ASHARE_PRICE_VENDOR=tencent
```

`ashare_price_vendor` 只接受 `eastmoney` 或 `tencent`。它同时控制行情、技术指标和 `get_verified_market_snapshot`；不能让一个工具用腾讯、另一个偷偷使用 Yahoo。未知名称、逗号列表或失败/空响应均不会触发其他国内或外国源的自动回退。用户可明确改选东方财富后重新运行，但两个源的历史修订和单位不能混接成一条序列。

## 单位契约与证据

已核对 [AKShare 官方实现（固定提交）](https://github.com/akfamily/akshare/blob/68f2977203a07d5b3e82d747904f2afb0dc525fc/akshare/stock/quote/stock_hist_tx.py) 和[官方文档源](https://github.com/akfamily/akshare/blob/68f2977203a07d5b3e82d747904f2afb0dc525fc/docs/data/stock/stock_quote.md)。本实现使用相同公开腾讯端点 `https://proxy.finance.qq.com/ifzqgtimg/appstock/app/newfqkline/get`，只读取 `day` 不复权序列，不安装或执行 AKShare 代码。

已识别的 11 字段日线中，位置 0 是日期，1/2/3/4 是开/收/高/低，5 是原始成交量，7 是原始换手率，8 是独立的原始成交额。其余字段不解释或用于推导投资结论。

| 字段 | 本阶段原始契约 | 标准输出 |
| --- | --- | --- |
| OHLC | 人民币元/股 | 同单位 |
| 成交量 | 手，包括深市 `000` 个股 | `VolumeLots` 保留原始手数；`Volume=VolumeLots×100` 股 |
| 成交额 | 万元 | `AmountTenThousandYuan` 保留原始值；`Amount=原始值×10000` 元 |
| 换手率 | 百分数 | `Turnover=原始值/100`，小数表示 |

官方 AKShare 代码对 `sz000` 豁免成交量乘 100，这与 2026-10-29 在本机对 `sz000001` 的实际字段一致性检查冲突：若把原始成交量当股，原始成交额换算后的成交均价会超出当天高低价；按手乘 100 后在区间内。`sh603179` 同样通过按手换算的校验。因此这里明确使用固定手数契约，不复制该豁免。

每条非零成交的数据都按固定契约检查 `源成交额（元）/源成交量（股）` 是否在当日最低与最高价范围内，来源舍入容差最多 0.02 元且不超过最低价的 1%。**这只是独立字段的一致性校验，不是生成成交额，也不动态猜乘数。** 校验失败、零量/零额不一致、非有限数、负值、缺少成交额、未知字段布局等会返回不可用；全窗口均为零成交时也无法验证单位，会返回不可用。不会试另一个倍数、用价格乘量补金额，或把错误数字传给指标。

该检查能发现本次 100 倍单位错误，但不能独立证明行情的真实性、覆盖完整性或任何历史版本。源手数可能经舍入，不宣称逐笔精确股数。

## 日期、范围与未支持项

- 与东方财富共用 `ashare_market.py` 的上海时区、已完成交易日和指标/快照内核。当天整根日线保守排除，即使已过 15:00；不使用响应中的当前 `qt` 报价或公司资料填充历史数据。
- 只支持不复权。缺少 `day` 时不会改取 `qfqday`/`hfqday`。除权除息缺口依旧影响指标；A 股收益/alpha 自动结算仍禁用。
- 单次最多 730 个自然日、640 条原始记录；指标预热取最多 730 天。服务器可能返回窗口外的有限记录，都会在本地截去；不逐年循环或扫描市场。
- 支持沪市主板、深市主板及创业板的现有代码识别范围。腾讯科创板 `688` 的量单位尚未独立验证，明确返回不可用；可明确选用第一阶段的东方财富适配，但不会自动切源。北交所、指数、B 股、基金等仍不属于本适配。
- 缺失最新应有交易日返回不可用，不用旧收盘价补当前行。窗口内缺失行不前向填充，也不保证可区分停牌和供应商遗漏。
- 国内综合新闻/社交舆情、龙虎榜、资金流、机构账户、数值财报、盘中价、复权收益评分尚未实现。缺少数据不是无风险或中性信号。

## 免费验收

在项目已有环境中运行；不需要安装新包或填写任何 Key：

```bash
python examples/verify_ashare_public.py --vendor tencent --full \
  --start 2026-10-20 --as-of 2026-10-28
```

默认只检查 `603179`、`000001`，最多允许两只。`--full` 检查 RSI、SMA200 预热、快照与行情最新行/来源一致性，以及公告可达性。只输出状态、单位和日期元数据；不运行 LLM，不保存或公开原始行情和公告正文。

2026-10-29 23:20:48～23:20:49（上海时间）本机验收结果：两只股票各有 7 条窗口内有效日线，日期为 10/20、21、22、23、26、27、28，最新日为 2026-10-28。两者 RSI 与快照一致，最新 OHLCV/成交额一致，SMA200 可用，公告索引均可达且有可验证条目。6 次腾讯日线请求和 2 次公告请求均为 HTTP 200；未触发回退或重试。

网络请求保持 TLS 校验、禁重定向、无自动重试，腾讯连接/读取超时为 5/8 秒。沿用本机现有网络；没有修改代理、Surge、VPN、启动器或原部署。域名中的 `proxy` 是腾讯端点名称，不代表本实现保证物理直连。此次成功不能保证以后稳定，来源出现 403/429、登录或其他访问限制时停止请求。

离线测试覆盖合成协议、`sz000` 手/股错误、万元/元、金额缺失、不复权、未来/当天截断、节假日、陈旧/空数据、未知布局、限流和 TLS 失败、来源锁定及真实工具到快照的一致性。所有提交的 fixture 均为合成数据。数据权利与开源软件许可分别适用；未获得数据的再分发或商用授权，生产/批量用途仍须核实来源条款。
